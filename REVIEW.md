# Review

- [fixed] correctness: ISO timestamps with a non-UTC offset (`2024-07-01T00:00:00-07:00`, `... -0700`) were read as UTC because everything after the seconds was silently ignored, shifting every hour and day by the offset (src/time.rs:64) -> trailing numeric offsets are now applied, fractional seconds are skipped explicitly, and any other trailing text (e.g. `PDT`) is rejected so the row counts as unreadable. Tests: `time::tests::applies_non_utc_offsets`, `rejects_trailing_garbage`.
- [fixed] correctness: one row with invalid UTF-8, which is common on SD cards after a power loss, aborted the whole file with "CSV error" (src/input.rs:77) -> rows are now read as byte records, and a corrupt row is skipped and counted as unreadable. Test: `input::tests::corrupt_bytes_skip_only_that_row`.
- [fixed] correctness/honesty: daily means, maxima and NowCast were displayed rounded to 0.1, but the AQI and the "days above 35.4" count use the truncated value. A day with a mean of 35.46 showed as "35.5" next to "Moderate", and "Highest day ... 35.5" appeared alongside "days above 35.4: 0" (src/output.rs:15,49,77-78,170) -> these values are now displayed truncated to 0.1, matching the AQI input. Test: `output::tests::displayed_daily_values_match_aqi_truncation`. The CLI test expectation and the README example changed from 98.2 to 98.1.
- [fixed] honesty: README did not say that concentrations above 325.4 µg/m³ are capped at AQI 500, how timestamp offsets are handled, or that displayed values are truncated (README.md Method/Input files) -> documented.
- [checked, no change] harm/correctness: I checked whether the 5-piece equation should take cf_1 rather than cf_atm, since using the wrong input would under-report smoke. EPA's 2021 extension webinar gives the piecewise form with the 0.786 middle slope and the 2.966 + 0.69x + 8.84e-4x² high piece specifically for PA cf_atm, so using `pm2.5_atm` is correct. Boundary blends and continuity match. The tool outputs no MAC address, location or other identifying data. Install instructions already use the `SignalForHumanity/purpleair-epa-correct` repo URL.
- [unfixed] correctness (minor): `merge` keeps the first row when a timestamp is duplicated, even if that row has missing values and a later duplicate is complete (src/input.rs merge). Exact-timestamp duplicates with differing content are rare. Left as documented behaviour.
- [unfixed] design: one expected-sample count applies to all merged files. Merging 2-minute SD data with an hourly export flags the hourly part as incomplete. This fails safe (no false values), and changing it would be a feature, not a fix.

The core science holds up: the EPA extended correction on cf_atm, the 5 µg/m³ and 70 % A/B check, the 90 % completeness rule, the 2024 AQI breakpoints with truncation, and NowCast all match the published methods. I found no charter harm: the data stays local, no identifiers are output, and the non-regulatory caveat is printed by default. The real bugs were in handling messy input. Timestamps with a local offset were silently treated as UTC, which mislabels hours and days. A single corrupt SD-card row threw away an entire day's file. A display inconsistency let the daily table show a value that seemed to contradict its own AQI category, which is the kind of thing that gets a community group's numbers dismissed. Each fix came with a test that failed before the change. `cargo fmt --check`, `cargo clippy --all-targets -D warnings`, `cargo test` (51 tests) and `cargo audit` all pass.
